# PAC Testing Guide

Everything here runs outside Roblox Studio. There is no playtest step: the same checks
that used to require starting the editor run from the command line, which is what makes
them cheap enough to run on every change.

```bash
lune run tools/run-tests.luau
```

Comments in this repository are written in English and explain *why* a line exists
rather than what it does. The same applies to new suites.

## What runs where

| Place | Runs under | What it covers |
|---|---|---|
| `tools/check.luau` | external tools | syntax, formatting, types and lint |
| `tests/*.luau` | `lune` | behaviour of pure logic |
| `src/shared/packages/SkillConstructor/tests/*.luau` | `lune` (and Studio) | blueprint to skill emission |

`tests/` is scanned recursively, so a new suite is picked up by name without touching
any list. `tests/baseline/` holds data for the gates and is skipped.

## Quality gates

Three gates, ordered by cost. Each one is only worth running if the previous is clean.

### syntax

`luau-compile --only-parse` over every first-party `.luau`. It knows nothing about
Roblox, but it is the fastest possible check that a file parses.

### format

`stylua --check`, run twice: once with `--line-endings=Unix` and once with
`--line-endings=Windows`. A file passes if it passes either pass, because the Windows
checkout carries CRLF while `stylua.toml` asks for Unix, and that difference is not a
formatting mistake. `tools/format.luau --fix` groups files by their current endings and
formats each group with the matching flag, so fixing never rewrites line endings across
the repository.

### analyze

`luau-lsp analyze` with two inputs it needs to be useful:

- `--defs=globalTypes.d.luau` — the Roblox global definitions. Without them every use of
  `game`, `Vector3`, `CFrame` or `Instance` is an "unknown global" error.
- `--sourcemap=sourcemap.json` — the Rojo sourcemap, regenerated by the gate itself
  (`rojo sourcemap --include-non-scripts`, ~200 ms). Without it, `require` paths do not
  resolve and project types such as `types.Character` come out unknown.

`--base-luaurc=.luaurc` is required for `@lune/*` to resolve; run `lune setup` once so
those definitions exist.

Two details the gate works around:

- **The exit code is always 0**, even with type errors. The gate parses
  `--formatter=plain` output instead.
- **Diagnostics arrive in two shapes.** One names a file that was passed in, the other
  names a module that was pulled in as a dependency and repeats for every file that
  requires it. The gate keeps only the first shape, otherwise vendored frameworks
  (Crane, Proxy, Signal, ...) would drown the report in their own pre-existing issues.

## Baselines

`src` already contains findings: dead imports, unused locals, type gaps in framework
code. Those are recorded in `tests/baseline/` and do not fail the gate. Only new
findings do — a baseline is a ratchet, not a waiver.

```bash
lune run tools/check.luau --update-baseline   # after reviewing what changed
```

`tools/` and `tests/` are held to zero findings: there is no excuse for new ones in code
that only exists to check the rest.

Reading the current numbers:

- `tests/baseline/analysis.txt` — type and lint diagnostics known in `src`
- `tests/baseline/format.txt` — files that were already unformatted

## Machine-readable output

```bash
lune run tools/check.luau --json
lune run tools/run-tests.luau --json
```

Both print a single JSON document and exit non-zero on failure, so an agent or a CI job
can consume them without parsing text. Gate results carry `status`, `checked`, `known`,
`added`, `removed` and `failures`; suite results carry `ok`, `durationMs` and the summary
line.

## Missing tools

A missing binary skips its gate and says so in the report — a machine without `stylua`
can still run the suites. `--strict` turns a skipped gate into a failure, which is the
right setting for CI: "nothing was checked" and "everything is clean" should not look
the same.

Lookup order: `PAC_TOOLS_DIR`, the directory of the running `lune`, `<root>/.tools`,
`PATH`. `LUAU_DEFS` overrides the location of `globalTypes.d.luau`, `PAC_ROOT` the
repository root.

## Adding a suite

Drop a `.luau` file into `tests/`. Use the style of the existing ones: a local `check`
helper, a `passed`/`failures` pair, and a final line with both counts.

```luau
--!strict
local passed = 0
local failures: { string } = {}

local function check(name: string, condition: boolean, detail: string?)
	if condition then
		passed += 1
		return
	end

	table.insert(failures, if detail ~= nil then `{name}: {detail}` else name)
end

-- ... checks ...

print(`[tests.example] passed: {passed}, failed: {#failures}`)

if #failures > 0 then
	error(table.concat(failures, "\n"), 0)
end
```

A non-zero exit code marks the suite as failed, so `error` (or `process.exit(1)`) is what
makes a failure visible to the runner.
