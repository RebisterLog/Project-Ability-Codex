# Ввод и BindService

Бинды лежат в `src/shared/configs/Specs.luau` в таблице `Binds` каждого спека. Бинд сопоставляет id скилла с `Enum.KeyCode` или `Enum.UserInputType` (кнопки мыши и тач поддерживаются). При надевании спека эти значения могут быть заменены переопределением для конкретного игрока.

## Кастомные бинды и панель скиллов

`src/shared/configs/Binds.luau` — список разрешённых клавиш, которые игрок может назначить. Его таблица `HiddenSkills` перечисляет id скиллов, для которых ячейка на панели вообще не создаётся (сейчас `Run`), при этом их бинды продолжают работать через `BindService`. Панель скиллов (`SkillBarComponent` + `SkillBarView`) показывает только включённые скиллы с биндом, в порядке `Spec`, затем `SubSpec`. Для анимации заполнения и числового таймера она использует `Parameters.ReleaseTime` из Proxy; полная длительность кулдауна на клиент не реплицируется.

Удержание левой кнопки мыши на ячейке одну секунду включает режим ребиндинга. Следующая клавиша из списка отправляется пакетом `RebindSkill({ SpecName, SkillId, Bind })`, где `Bind` — `tostring(EnumItem)`, потому что ByteNet не умеет сериализовать Enum. `SpecModule:Rebind` проверяет владение спеком и наличие скилла, сохраняет бинд в `PlayerSaveData.SpecBinds[specName][skillId]` и сразу применяет его к живому скиллу через `skill:SetBind`, если этот спек надет.

Бинды ключуются по **имени спека**, а не по UUID купленного спека, поэтому после смены спека и возврата выбор игрока восстанавливается. `SpecModule:EquipSpec` переводит сохранённые строки обратно в EnumItems через тот же список и передаёт их в `SpecService:CreateSpec` как переопределение для игрока — оно имеет приоритет над `Specs.luau`. Дубли клавиш между скиллами допустимы и разрешаются описанным ниже порядком слотов и id. `BindService.SkillActivated` срабатывает один раз на нажатие и ненадолго сжимает ячейку через `scope:Spring`.

Ячейки расставляются через явный `LayoutOrder`: сначала все скиллы `Spec`, затем `SubSpec`, внутри слота — по алфавиту id. Спек может задать `Palette = { BackgroundColor, NameColor, CooldownColor, TimerColor, BindColor, BindTextColor }` в `Specs.luau` — по цвету на каждый элемент ячейки; у сабспека своя запись и, значит, своя палитра. Незаданные цвета берутся из встроенных значений.

## Как ввод доходит до скилла

```
клавиша / мышь / тач
  -> клиентский BindService
  -> пакет StartSkill({ Id, AimPoint? })
  -> серверный SkillService проверяет
  -> spec:ActivateSkill(skillId, aimPoint)
  -> Skill:Activate(aimPoint)
```

## AimPoint (положение курсора в мире)

`StartSkill` — это структура, а не голая строка: `{ Id: string, AimPoint: Vector3? }`. Точку шлют только скиллы с `AimRequired = true` в серверных данных; остальные бинды шлют `nil`, поэтому бюджет клиент→сервер для существующих скиллов не меняется.

- **Обычная камера:** берётся `Mouse.Hit.Position`, ограниченная `MAX_AIM_DISTANCE` (120 стадов) от `HumanoidRootPart` персонажа.
- **ShiftLock:** когда `TargetLockService.Locked == true` или `UserInputService.MouseBehavior == Enum.MouseBehavior.LockCenter`, курсор закреплён в центре и `Mouse.Hit` бессмыслен. Клиент шлёт `root.Position + root.CFrame.LookVector * MAX_AIM_DISTANCE` — самую дальнюю точку по направлению взгляда персонажа.
- **Нет персонажа / нет `Mouse.Hit`:** используется тот же запасной вариант по LookVector.

Сервер не доверяет точке для определения попаданий: это только подсказка направления для запуска снаряда. `SkillService:ActivateSkill(character, skillId, aimPoint)` передаёт её через `Spec:ActivateSkill` в `Skill:Activate(aimPoint)` и дальше в `SkillData.Activate(self, aimPoint)`. Скиллы, которым прицел не нужен, просто игнорируют лишний аргумент.

Клиент ограничивает точку в `BindService:AimPointFor` (120 стадов от `HumanoidRootPart` кастера); теперь `SkillService:ActivateSkill` применяет тот же кламп на сервере, поэтому точки от ботов и вызовов через Studio Bridge тоже попадают под ограничение. `nil` остаётся без изменений. Точку получают только скиллы с `AimRequired = true` в серверных данных (сейчас `Knives`): флаг реплицируется в `Skills[slot][id].Parameters.AimRequired` и читается и клиентом, и ботами. Это позволяет не отправлять вектор для каждого удерживаемого бинда.

## Важные моменты

- **Опции Hold нет.** Пока клавиша нажата, бинд запрашивается повторно, и сервер проверяет каждый запрос. Общий бюджет — примерно 12 пакетов/сек на все удерживаемые клавиши. После отпускания `StopSkill` повторяется короткое время, чтобы потерянный пакет не оставил скилл застрявшим.
- **Скиллы-переключатели исключены из повтора:** `Run` и `Summon` объявляют `Toggle = true` в серверных данных скилла; флаг реплицируется как `Parameters.Toggle`.
- **Конфликт биндов:** кандидаты сортируются по слоту (`Spec` перед `SubSpec`), затем по алфавиту id. Первый кандидат, который может быть применён сейчас, получает клавишу. Кандидат, заблокированный кулдауном, отключённым состоянием, отсутствующим скиллом или состоянием персонажа, передаёт клавишу следующему. Если никто не может стартовать, клавишу удерживает самый приоритетный кандидат до отпускания.
- Проверка на сервере авторитетна: кулдаун, стан, рэгдолл и состояние жизни проверяются до `Activate`. См. [[Combat pipeline (RU)]].

## Типичная таблица биндов

```luau
Binds = {
    ["Punch"] = Enum.UserInputType.MouseButton1,
    ["Block"] = Enum.KeyCode.F,
    ["Dash"]  = Enum.KeyCode.C,
    ["Run"]   = Enum.KeyCode.LeftControl,
    ["Grab"]  = Enum.KeyCode.X,
}
```
